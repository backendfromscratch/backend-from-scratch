## The problem

Ana wants the shop's website to have an “Under €25” section. In [Phase 2](/en/phase-2/), her nginx served fixed files: whatever was on the disk, as it was. But a file can't choose. To answer “what costs less than €25?”, the server has to go through the products, compare each price, keep the ones that pass and turn the result into text to send it over HTTP.

That's a program, and in this phase you write it in <Term id="javascript">JavaScript</Term>, the language that <Term id="nodejs">Node.js</Term> runs. You don't need the whole language: a small server uses a dozen ideas, and they are the ones in this lesson.

If you already program in JavaScript, you can skip to [lesson 3, “TypeScript”](/en/phase-3/typescript-with-node/). First, take the quiz at the end: if you get all six right, you won't miss anything.

## The analogy

<Analogy>

Think of the kitchen of a café:

- **The jars on the shelf** have a label, “salt” or “sugar.” The label is the name, and what's inside is the value: that's a variable.
- **Each dish on the menu has its card**, with fixed fields: name, price, allergens. That's an object.
- **The cards go in a binder**, in order: the first, the second, the third. That's an array.
- **The omelet recipe** says what to do with some ingredients and gives you back a dish. It's written once and works for every omelet: that's a function.
- **The order ticket** is the slip where the waiter writes down the order, in a format the kitchen understands. That's JSON: data turned into text so it can travel.
- **If you order something that takes a while**, they give you a number and you keep chatting until they call it. The number is a promise, and waiting for them to call it is `await`.

<div slot="limits">

- You can peel the label off a jar and stick it on another one. Not a name created with `const`: it always holds the same value. Mind you, if that value is an object, what's inside can change: you'll see it with the mug.
- A cook understands “a pinch of salt.” JavaScript does exactly what you write: with one comma missing, the program doesn't even start.
- In the binder, the first card is number 1. In an array, the first one is number 0.

</div>

</Analogy>

## How it really works

### Experiment without fear: the REPL

Open the terminal in the project folder, `~/backend-course/phase-3/shop-api`, and type `node`. The <Term id="repl">REPL</Term> you met in [lesson 1, “Node.js”](/en/phase-3/what-is-node-js/) opens: you type a line, press Enter and Node answers with its result. You leave with `.exit` or with <kbd>Ctrl</kbd> + <kbd>D</kbd>.

Try every example in this section in it, in order and without closing it: some use values from the earlier ones. The outputs are from Node 26.11.1; with another version, some error message may change.

### Values: text, numbers and true or false

Everything a program handles is a value. These are the three simplest kinds:

<TryIt
  title="In the REPL: three values"
  lang="js"
  cmd={`'Mug'
8.5 * 2
20 < 25`}
  output={`'Mug'
17
true`}
>

- `'Mug'` is **text** (a *string*): it goes in quotes, single or double.
- `8.5 * 2` is an operation with **numbers**. Decimals use a point, and there are no commas for thousands: one thousand is `1000`. `*` means multiply.
- `20 < 25` is a comparison, and its result is `true` (or `false`). The comparisons are `<`, `>`, `<=`, `>=`, `===` (equal) and `!==` (not equal).

</TryIt>

An oddity that matters in a shop: decimals aren't always exact. `0.1 + 0.2` gives `0.30000000000000004`, because the computer stores numbers in binary and some decimals don't fit exactly. That's why prices are usually stored in cents, as whole numbers: €8.50 is `850`.

### Saving a value with a name: const and let

A <Term id="variable">variable</Term> is a name that holds a value so you can use it later. You create it with `const` if you won't give it another value, and with `let` if you will:

<TryIt
  title="In the REPL: const and let"
  lang="js"
  cmd={`const price = 8.5
price * 2
price = 9
let quantity = 1
quantity = 3`}
  output={`undefined
17
Uncaught TypeError: Assignment to constant variable.
undefined
3`}
>

One output per line. Creating a variable has no result, and the REPL says so with `undefined`, “no value.” After that, `price` is `8.5` in any calculation.

`price = 9` fails: `price` was created with `const`, and that's what the error says: you can't assign a new value to a constant. With `let quantity`, on the other hand, you can change the value as many times as you want, and the REPL shows you the new one, `3`.

</TryIt>

The `=` only means “store this here.” To compare, you use `===`. Use `const` whenever you can: if you see `let`, you know that value is going to change. (In old code you'll see `var`, the way it was done before 2015: you don't need it.)

### Text with gaps: backticks

If you write text between backticks (`` ` ``), you can put values inside it with `${…}`. They're called *template strings*:

<TryIt
  title="In the REPL: text with a gap"
  lang="js"
  cmd={"`Two mugs: ${price * 2} €`"}
  output="'Two mugs: 17 €'"
>

Node works out what's inside `${…}` and puts it in its place. On a US keyboard, the backtick is the key in the top-left corner, under <kbd>Esc</kbd> and to the left of the <kbd>1</kbd>.

</TryIt>

### Objects: a product with its data

A product isn't a single value: it has a number, a name and a price. An <Term id="object">object</Term> puts them together, each with its name:

<TryIt
  title="In the REPL: the mug"
  lang="js"
  cmd={`const mug = { id: 2, name: 'Mug', price: 8.5 }
mug.name
mug.price = 9
mug`}
  output={`undefined
'Mug'
9
{ id: 2, name: 'Mug', price: 9 }`}
>

- The braces `{ … }` create the object. Inside, each piece of data is a name, a colon and its value, separated by commas. Each piece of data is called a **property**.
- `mug.name` reads a property: the object's name, a period and the property's name.
- `mug.price = 9` changes one, even though `mug` is `const`. The name `mug` still points to the same object; what changes is what's inside.

</TryIt>

### Arrays: a list in order

An <Term id="array">array</Term> is a list of values in order, between square brackets. This is how `products.js`, the first file of this lesson, begins:

<ProjectCode file="shop-api/02-javascript/products.js" region="products" />

- The first line is a **comment**: it starts with `//`, and Node doesn't read it. It's for whoever reads the code.
- `const products = [ … ]` creates an array of three objects, separated by commas. The comma after the last one is optional.
- The line breaks only help reading: for JavaScript it's a single instruction, which the `;` at the end closes.

You read each element by its position, which starts at 0:

<TryIt
  title="In the REPL: positions"
  lang="js"
  cmd={`const prices = [20, 8.5, 35]
prices[0]
prices[3]
prices.length`}
  output={`undefined
20
undefined
3`}
>

`prices[0]` is the first one, and `prices[3]` would be the fourth, which doesn't exist: JavaScript doesn't give an error, it returns `undefined`. `length` is how many elements it has, so the last one is always the one at position `length - 1`.

</TryIt>

### Functions: a piece of code with a name

A <Term id="function">function</Term> is a piece of code with a name that takes data and returns a result. This one works out what several units of a product cost:

<ProjectCode file="shop-api/02-javascript/products.js" region="total" />

Word by word:

- `function total` creates a function called `total`.
- `(product, quantity)` are its **parameters**: the names that the data it receives will have inside the function.
- What goes between the braces is what it does each time it's used.
- `return` gives the result back to whoever called it.

Writing it doesn't run anything. It runs when you **call it**, with its name and the data in parentheses: `total(products[1], 2)` gives `17`. The same function works for the T-shirt, the hoodie and the products that arrive tomorrow.

### Choosing and transforming a list: filter and map

Now, Ana's section:

<ProjectCode file="shop-api/02-javascript/products.js" region="filter" />

- `(product) => product.price < 25` is an **arrow function**: a short function with no name. To the left of `=>`, what it receives; to the right, what it returns. Here it returns `true` or `false`.
- `products.filter(…)` calls that function with each product and returns a new array, only with the ones that gave `true`: the T-shirt and the mug.
- `cheap.map(…)` calls its function with each element and returns an array of the same size, with what it returned each time: `['T-shirt', 'Mug']`.
- `names.join(', ')` joins the pieces of text in the list into one, with a comma and a space between them.
- `console.log(…)` writes a line in the terminal.

Neither `filter` nor `map` changes `products`: both create a new array.

### Deciding with if and repeating with for…of

`if` runs a block only if a condition is met, and `else` runs the other one. The condition goes in parentheses, and each block, in braces:

<TryIt
  title="In the REPL: if and else"
  lang="js"
  cmd={`if (mug.price < 25) { console.log('Cheap') } else { console.log('Expensive') }`}
  output={`Cheap
undefined`}
>

The mug costs 9, so the first block runs. `Cheap` is written by `console.log`, and `undefined` is the REPL saying that the `if` has no result.

</TryIt>

And `for…of` repeats a block once for each element of an array:

<ProjectCode file="shop-api/02-javascript/products.js" region="loop" />

It reads “for each `product` of `products`.” On each pass, `product` is the next element, and the line inside calls `total` with it. This is called a **loop**: three products, three passes, three lines in the terminal.

### JSON: data turned into text

An object lives in the program's memory. To send it over HTTP you have to turn it into text, and the format almost every <Term id="api">API</Term> uses is <Term id="json">JSON</Term>, the one you saw in the body of requests in [Phase 2](/en/phase-2/http-request-and-response/):

<ProjectCode file="shop-api/02-javascript/products.js" region="json" />

- `JSON.stringify(products[1])` turns the mug into text: `{"id":2,"name":"Mug","price":8.5}`. That's what your server will send as a response.
- `JSON.parse('…')` does the opposite: it takes a JSON text and returns an object, with its properties. That's what your server will do with the body of a `POST`.

JSON looks like a JavaScript object, but it's stricter: names and text values always go in double quotes. Otherwise, `JSON.parse` fails:

<TryIt
  title="In the REPL: badly written JSON"
  lang="js"
  cmd={`JSON.parse("{name: 'Cap'}")`}
  output={`Uncaught:
SyntaxError: Expected property name or '}' in JSON at position 1 (line 1 column 2)`}
>

It expected a property name or a `}` at position 1: right where the quote before `name` is missing (positions are counted from 0). When a client sends a body like that, your server will have to answer with a `400`, as you saw in [“Status codes”](/en/phase-2/http-status-codes/).

</TryIt>

### Waiting for what takes time: promises, async and await

Reading a file, or waiting for another server's response, takes time. Look at what `readFile`, the function from lesson 1 that reads files, returns. In the REPL you don't need `import`: Node's <Term id="module">modules</Term> are at hand, and `fs.promises.readFile` is that same function:

<TryIt
  title="In the REPL: a promise"
  lang="js"
  cmd={`fs.promises.readFile('products.json', 'utf8')`}
  output="Promise { <pending> }"
>

`'utf8'` asks for the content as text. But it doesn't return that text: it returns a *pending* **promise**. The text isn't there yet, but it will come.

</TryIt>

That's what a <Term id="promise">promise</Term> is: a value that will arrive later. To use what it brings you have to wait for it, and that's what <Term id="async-await">async and await</Term> are for. This is the second file of this lesson, `wait.js`:

<ProjectCode file="shop-api/02-javascript/wait.js" />

- `import { readFile } …` brings in the function that reads files, as in lesson 1.
- `async function countProducts(file)` creates a function marked as `async`: inside it you can use `await`, and whatever it returns will arrive as a promise.
- `await readFile(…)` waits for the promise to bring the text, and stores it in `text`.
- `return JSON.parse(text).length` turns the text into an array and returns how many elements it has.
- At the bottom, `await countProducts(…)` waits for that function. Here `await` is outside a function, and that's allowed: your files are modules, because of the `"type": "module"` in the `package.json` from lesson 1.

**Waiting isn't stopping.** While an `await` waits for the disk or the network, Node can do other things: in a server, serve other clients. How it manages that is [lesson 9, “Event loop”](/en/phase-3/node-event-loop/).

## You have already seen it

- **In DevTools** ([how to open them](/en/phase-2/#before-you-start-devtools)): in the **Network** tab, an API's response is a JSON text. Behind it, a server did a `JSON.stringify`, and the page will do a `JSON.parse`.
- **In the [CORS lesson](/en/phase-2/what-is-cors/)** you wrote `await fetch(…).then(r => r.json())`. Now you can read it: `fetch` returns a promise, `.then(…)` tells it what to do when it's fulfilled, `r => r.json()` is an arrow function that turns the response into data, and `await` waits for the result.
- **The spinning circle while a page loads** is often an unfulfilled promise: the data hasn't arrived.

## Common mistakes

- **`=` to compare.** `=` stores a value; to compare, you use `===`. And avoid `==`: it converts before comparing, and `9 == '9'` gives `true`, while `9 === '9'` gives `false`.
- **Forgetting the `await`.** The program carries on with a promise instead of the value, with no error: `[object Promise]` inside text, or `undefined` when reading a property.
- **Counting from 1.** The first one is `[0]`, and the last one, `[length - 1]`. Asking for a position that doesn't exist gives no error: it gives `undefined`.
- **Prices with decimals.** `0.1 + 0.2` doesn't give `0.3`. Store cents as whole numbers. And don't store them as text: `'8.5' + '20'` gives `'8.520'`, because `+` with text glues the pieces together.
- **JSON with single quotes or no quotes.** `JSON.parse` only accepts double quotes, in names and in text values.
- **Thinking `const` freezes an object.** It stops you giving the variable another value, but its properties can still change.

## Summary

- The basic values are text, numbers and `true`/`false`. You store them in variables with `const` or, if they're going to change, with `let`.
- An object groups data with names (`mug.price`), and an array puts it in order, counting from 0.
- A function takes data and returns a result. `filter` chooses elements from an array, `map` transforms them and `for…of` goes through them one by one.
- `JSON.stringify` turns an object into text to send it, and `JSON.parse` turns a JSON text into an object.
- What takes time returns a promise, and `await`, inside an `async` function, waits for its value. Without `await`, you have the promise and not the value.
